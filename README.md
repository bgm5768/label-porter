# 라벨 포터

**버전 관리 기준: v1 (2026-10-20)** — 프로그램 2.4.0을 첫 Git 기준 버전으로 보관합니다. `v1` 태그로 이 상태를 다시 확인할 수 있습니다. 현재 프로그램은 **2.5.0**이며 변경 내역은 [CHANGELOG.md](CHANGELOG.md)에 기록합니다.

플랫폼 DB에 접근하지 않고, 어드민에서 내려받은 작업 결과를 원본 라벨링 JSON에 반영하는 Windows 데스크톱 프로그램입니다. 모든 데이터 처리는 로컬에서 이루어집니다. 외부 서비스나 AI 호출이 없습니다.

원본 폴더는 읽기만 합니다. 매 실행마다 새 폴더에 원본 전체를 복사하고, 연결키가 확인되고 검증을 통과한 레코드의 지정 필드만 수정합니다. 결과에 없는 파일·레코드는 보존합니다. 목록 내부의 추가·삭제는 사용자가 선택한 규칙에 따릅니다.

**2.4 개선:** 결과 목록으로 전체 재구성하는 규칙을 추가했습니다. 사용자가 전체 교체를 선택한 경우 어절 추가·삭제·분할·병합도 반영합니다. 독립된 발음 오류 태그는 수정 규칙에 포함하지 않으면 원본 그대로 유지됩니다. 참조 재연결·불확실한 태그의 별도 보관은 규칙에서 명시적으로 선택한 경우에만 수행합니다. 상단 **JSON 뷰어**에서 최상위 항목 수와 내부 배열 개수를 확인할 수 있습니다. 2.3의 보고서 페이지 이동·전체 검색·대용량 분할 읽기도 유지됩니다.

**AI 규칙 흐름:** AI 규칙 작성을 기본 흐름으로 사용합니다. 원본 라벨·플랫폼 결과·MD 가이드를 AI에 전달하고 받은 규칙을 불러옵니다. ‘필드 연결’ 탭은 연결된 기준·수정값·반복 목록·기존값 검사만 읽기 전용으로 보여 줍니다. 수정은 ‘AI에 수정 요청’에서 가이드·현재 규칙·요청을 복사해 AI에 전달합니다. 실제 데이터는 입력 단계에서 한 번 선택하고 전체 검증 후 복사본에 반영합니다.

## 실행

- Windows 실행 파일: `dist/v2.5/LabelPorter.exe`를 더블클릭합니다. Python 설치가 필요하지 않습니다.
- 소스 실행: Python 3.11 이상에서 `python -m label_porter` 또는 `start.cmd`를 실행합니다. 외부 패키지가 필요 없습니다. Windows 공식 Python의 Tkinter를 사용합니다.
- 상세 규칙 설명: [사용설명.md](사용설명.md)

## 화면에서 사용하기

1. **MD 파일 저장**으로 받은 문서와 보완 전 원본 라벨, 플랫폼 최종 결과를 AI에게 전달합니다.
2. **규칙 파일 열기**로 `project_profile.json`을 엽니다. JSON 텍스트는 ‘규칙 JSON 붙여넣기’로 가져옵니다.
3. 읽기 전용 **필드 연결 / 조건·검증**을 확인하고 **연결 확인 완료 · 입력 선택**을 누릅니다. 직접 선을 연결하지 않습니다.
4. 실제 전체 원본 폴더, 결과 파일들, 저장 위치를 선택합니다.
5. **전체 데이터 검증 → 상세 보고서 → 복사본 저장** 순서로 진행합니다.

규칙을 고칠 때는 ‘AI에 수정 요청’에 원하는 변경을 적고 가이드·현재 규칙과 함께 복사합니다. 새로운 규칙 JSON을 받아 다시 불러옵니다. 프로그램 자체에는 AI 호출이나 데이터 외부 전송 기능이 없습니다. 기존 규칙 문법과 원본 보존·분리·보고서 기능은 유지됩니다.

자세한 내용은 [사용설명.md](사용설명.md)를 참고하세요.

## 선택 기능: JSON 한 건으로 직접 연결

프로젝트 규칙 화면에서 **선택 기능 · JSON 한 건으로 직접 연결하기**를 펼치고 **한 건으로 규칙 만들기**를 누릅니다. 기본 AI 규칙 흐름에서는 이 기능을 사용하지 않아도 됩니다.

1. 원본 라벨과 플랫폼 결과 또는 별도로 만든 보완 JSON을 선택합니다. 통합 JSON이면 레코드가 들어 있는 목록 위치를 확인합니다.
2. 원본·결과 항목 번호를 고르고 **이 한 건 비교**를 누릅니다. **양쪽 JSON 보기**에서 내용을 확인할 수 있습니다.
3. 같은 건을 찾을 ID나 파일명부터 연결한 다음, 원본에서 바꿀 필드와 결과에서 가져올 값을 연결합니다. 세부 설정에서 숫자 변환·소수 1자리 반올림 등을 선택할 수 있습니다.
4. **선택한 원본 1건 시험 적용**으로 변경 전후를 확인하고 규칙을 확정합니다.
5. 실제 처리할 전체 입력·저장 위치를 선택하고 기존과 같이 전체 검증 후 복사본을 저장합니다. 규칙은 ‘규칙 내보내기’로 저장할 수 있습니다.

선택한 두 행을 강제로 짝짓지 않습니다. 시험 적용은 원본 한 건의 연결키로 결과 전체에서 같은 건을 찾고, 중복 키는 읽은 원본·결과 전체에서 검사합니다. 표본 파일 선택은 전체 처리 범위로 자동 확대되지 않습니다. 다른 항목으로 바꿔 보아도 만든 연결은 유지됩니다. 목록의 안쪽 연결은 기본적으로 항목 ID를 대조하는 규칙이며, 분할·병합 등 복잡한 재구성 규칙은 기존 AI 규칙 기능을 이용하세요.

## 출력

자주 누르는 미리보기와 보관해야 할 반영 결과를 구분합니다.

```text
선택한 저장 폴더/
  미리보기/               가장 최근 미리보기 보고서 (다음 미리보기 때 갱신)
    reports/
    profile.json
    manifest.json
    run_status.json
  2026-10-19/
    001/                  이날 첫 번째 반영
      data/               원본 폴더 구조를 유지한 전체 복사본
      changed/labels/     실제 변경된 라벨
      unchanged/labels/   원본 그대로인 라벨
      unclassified/labels/ 해석 불가 라벨 (해당할 때만 생성)
      reports/
        report.html       집계·검토 보고서
        summary.json      기계가 읽는 집계
        records.csv       전체 상태·누락·중복·검토 사유
        changes.jsonl     필드별 변경 전후 값
        review_details.jsonl 전체 검토 사유·원본·플랫폼·실제 출력·후보 JSON
        review/           검토 레코드별 비교 HTML 및 전체 JSON
        partition_index.jsonl 원본 ↔ 분리본 위치
      profile.json        적용 규칙
      manifest.json       원본/결과 해시
      run_status.json     완료·검토·실패·중단 상태
    002/                  이날 두 번째 반영
  2026-10-20/
    001/                  다음 날 첫 번째 반영
```

날짜는 **한국 시간** 기준입니다. 순번은 같은 날짜 폴더의 가장 큰 숫자 다음으로 발급하며 999 다음에는 1000입니다. 미리보기는 순번을 사용하지 않습니다. 기존 실제 반영 결과와 이전 버전의 `run_...`, `preview_...` 폴더는 이동하거나 삭제하지 않습니다.

미리보기의 보고서·설정·명세는 최신 실행으로 갱신됩니다. 보관할 미리보기 보고서는 다음 검증 전에 따로 복사하세요. 같은 저장 위치에서 동시에 미리보기를 실행하면 두 번째 실행을 차단합니다. 프로젝트마다 저장 상위 폴더를 따로 지정하면 프로젝트별 최신 미리보기를 유지할 수 있습니다.

실패/중단된 반영에는 부분 복사본이 남을 수 있으며, `run_status.json`과 HTML 보고서에 표시합니다. 다음 실행은 새 순번으로 저장됩니다. 실패/중단된 결과를 완성본으로 사용하지 마세요.

통합 JSON은 레코드 단위로, 개별 JSON은 파일 단위로 분리합니다. 원래 파일명·상대 경로·라벨 구조를 유지하며 통합 JSON의 바깥 메타데이터는 변경하지 않습니다. 미변경은 검수 완료를 뜻하지 않으며 `records.csv`에 값 동일·결과 없음·조건 제외·검토 보류 사유가 구분됩니다.

분리 대상은 라벨 JSON입니다. 원본 폴더에 함께 들어 있는 다른 파일은 전체 `data/` 복사본에 보존합니다. 별도 원천데이터 폴더를 연결하거나 이미지·오디오를 두 그룹으로 분리하는 기능은 없습니다. 예전 규칙 파일의 `assets` 설정은 불러올 때 제외되며 라벨 반영 규칙은 유지됩니다.

## 보존 및 검증 정책

- 결과에 없는 원본은 그대로 보존하며 `no_result`로 보고합니다. 이것만으로 작업 누락이라고 판정하지 않습니다.
- 원본 키/결과 키가 중복되면 임의로 하나를 선택하지 않습니다. 관련 항목 전체를 보존하고 보고합니다.
- 빈 수정값·필드 누락·자료형 오류·동일성 확인 실패·시간 범위/참조 오류는 `review_required`입니다.
- 레코드 내 여러 필드 중 하나라도 실패하면 해당 레코드의 모든 변경을 취소합니다. 다른 정상 레코드는 반영할 수 있습니다.
- 원본의 다른 필드와 메타데이터, 미디어 파일, 결과에 없는 파일은 유지됩니다.
- 결과에 없는 배열 항목은 기본적으로 검토 대상입니다. 부분 결과임이 확실한 프로젝트는 `require_same_keys: false`로 기존 항목을 보존하며 처리할 수 있습니다.
- 새 객체 ID, 어절 분할/병합의 자동 추정은 하지 않습니다. 관계를 정의한 새 규칙/확장 작업이 필요합니다.
- 설정은 임의 Python/JavaScript를 실행하지 않습니다. 지원하는 연산만 사용합니다.
- 수정된 JSON의 공백/들여쓰기/숫자 표기 등 직렬화 표현은 달라질 수 있습니다. 구조·값·자료형을 보존하며, 수정되지 않은 파일은 바이트 그대로 복사합니다.

## AI로 프로젝트 규칙 만들기

[AI_규칙작성_가이드.md](AI_규칙작성_가이드.md)는 별도 파일 하나로 AI에 전달할 수 있습니다. 데이터 역할 확인, 고유 키와 필드 대응, 허용 문법, 배열 객체 연결, 단위 변환, 보존 정책, 검증 절차와 반환 형식을 정의합니다. 문서의 텍스트·객체·시간 구간 예제는 가상 구조이며 실제 프로젝트에 맞춰 작성하도록 안내합니다.

프로그램의 AI 가이드 탭과 사용 방법 탭은 배포에 포함된 같은 Markdown 원문을 표시합니다. 가이드는 실행 파일에도 내장되어 단독 EXE로 사용할 때도 읽기·복사·파일 저장이 가능합니다.

## 명령행

```powershell
python -m label_porter run --source 'C:\project\original_labels' --result 'C:\project\123_result.json' --config 'project_profile.json' --output 'C:\project\포팅결과' --preview
python -m label_porter run --source 'C:\project\original_labels' --result 'C:\project\123_result.json' --config 'project_profile.json' --output 'C:\project\포팅결과'
python -m label_porter validate-config 'project_profile.json'
```

여러 결과 파일은 `--result 'a.json' 'b.json'`처럼 지정합니다. 동일 프로젝트의 같은 규칙을 적용할 파일들만 묶습니다. 서로 다른 시점의 동일 작업 결과가 중복되면 충돌로 보고하므로, 최종 확정된 내보내기 파일을 선택하세요.

분리본을 만들지 않고 전체 `data`만 생성하려면 `--no-split`을 사용합니다.

종료 코드: `0` 정상 완료, `2` 처리는 완료됐지만 검토/매칭 오류 존재, `1` 입력 오류·실행 실패·중단. 결과 없는 원본(`no_result`)은 보존 상태이며 단독으로 종료 코드 2를 만들지 않습니다.

## 개발 및 검증

전체 테스트에는 Python의 Tkinter와 Node.js가 필요합니다. 기준 환경은 Windows, Python 3.13, Node.js 24입니다. 앱 실행에는 Node.js가 필요하지 않습니다.

```powershell
python -m unittest discover -s tests -v
python scripts/verify_run.py 'outputs\프로젝트\2026-10-19\001'
```

독립 검증 도구는 모든 원본이 실행 당시 해시와 같은지, 복사본에 파일 누락이 없는지, 수정되지 않은 파일이 바이트 단위로 같은지, 보고서에 기록된 변경 외의 변경이 없는지 검사합니다.

Windows 단일 실행 파일 빌드:

```powershell
python -m venv .venv

```

## 저장소에 포함하는 파일

소스 코드, 테스트와 가상 데이터, 규칙 예제, 사용 설명서, 빌드 설정을 관리합니다. 실제 라벨 데이터, 플랫폼 내보내기 파일, 검증 보고서, 실행 파일, 가상 환경, 개인 설정과 인증 정보는 포함하지 않습니다.

작업 데이터는 저장소 밖에 두거나 `.gitignore`에 지정된 `data/`, `inputs/`, `results/`, `outputs/` 폴더를 사용하세요. 개인 프로젝트 규칙은 `local_profiles/`에 보관하세요. `profiles/`는 배포용 예제이며 특정 작업에 적용하기 전에 조건을 확인해야 합니다. `.gitignore`는 임의 이름의 민감한 파일을 자동 판별하지 않으므로 커밋 전에 추가 파일 목록을 확인하세요.

## 적용 범위

원본은 JSON 기반 라벨링 파일을 지원합니다. 단일 객체, 배열, 중첩 레코드, JSONL, 여러 JSON 객체가 공백으로 이어진 파일을 처리합니다. 결과 입력은 같은 JSON 종류와 CSV를 지원합니다. CSV의 중첩 JSON 열은 설정에 명시해 해석합니다. 이미지·오디오·LLM·3D의 구분보다 **원본과 결과의 연결키, 수정할 필드, 단위, 객체 관계**가 설정의 기준입니다.

임의의 신규 스키마를 의미까지 자동 추론하는 프로그램은 아닙니다. XML/독자 바이너리 출력, 복잡한 구간 분할·병합, 좌표계 회전, 신규 객체 생성/삭제 정책은 추가 규칙/어댑터 개발 대상입니다. JSON 객체/배열 전체 교체도 명시적으로 설정할 수 있지만 내부 참조와 누락 항목을 프로젝트에서 검증해야 합니다.
