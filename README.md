# 라벨 포터

**버전 관리 기준: v1 (2026-10-20)** — 프로그램 2.4.0을 첫 Git 기준 버전으로 보관합니다. `v1` 태그로 이 상태를 다시 확인할 수 있습니다. 현재 프로그램은 **2.17.0**이며 변경 내역은 [CHANGELOG.md](CHANGELOG.md)에 기록합니다.

플랫폼 DB에 접근하지 않고, 어드민에서 내려받은 작업 결과를 원본 라벨링 JSON에 반영하는 Windows 데스크톱 프로그램입니다. 모든 데이터 처리는 로컬에서 이루어집니다. 외부 서비스나 AI 호출이 없습니다.

원본 폴더는 읽기만 합니다. 매 실행마다 새 폴더에 원본 전체를 복사하고, 연결키가 확인되고 검증을 통과한 레코드의 지정 필드만 수정합니다. 결과에 없는 파일·레코드는 보존합니다. 목록 내부의 추가·삭제는 사용자가 선택한 규칙에 따릅니다.

**2.4 개선:** 결과 목록으로 전체 재구성하는 규칙을 추가했습니다. 사용자가 전체 교체를 선택한 경우 어절 추가·삭제·분할·병합도 반영합니다. 독립된 발음 오류 태그는 수정 규칙에 포함하지 않으면 원본 그대로 유지됩니다. 참조 재연결·불확실한 태그의 별도 보관은 규칙에서 명시적으로 선택한 경우에만 수행합니다. 상단 **JSON 뷰어**에서 최상위 항목 수와 내부 배열 개수를 확인할 수 있습니다. 2.3의 보고서 페이지 이동·전체 검색·대용량 분할 읽기도 유지됩니다.

**AI 규칙 흐름:** AI 규칙 작성을 기본 흐름으로 사용합니다. 원본 라벨·플랫폼 결과·MD 가이드를 AI에 전달하고 받은 규칙을 불러옵니다. ‘필드 연결’ 탭은 연결된 기준·수정값·반복 목록·기존값 검사만 읽기 전용으로 보여 줍니다. ‘필드 연결 프리뷰’에서는 전체 입력을 검색·페이지 이동하고 레코드를 선택하여 실제 연결값과 적용 후 JSON을 확인합니다. 읽은 데이터와 화면 상태는 다른 단계에 다녀와도 유지됩니다. 수정은 가이드·현재 규칙·요청 내용을 AI에 전달해 새 규칙을 받습니다. 실제 데이터는 입력 단계에서 한 번 선택하고 전체 검증 후 복사본에 반영합니다.

## 처리 결과서

집계 카드를 누르면 작업 결과·처리 완료·원본·보완·변경 필드·검토/오류·짝이 없는 데이터·조건 제외·파일 오류 목록으로 이동합니다. 분류 및 상태 필터, 전체 검색, 25/50/100건 페이지 이동을 함께 사용합니다. 정상 완료 항목도 상세 비교에서 원본·보완·출력 JSON과 변경 전후 값을 확인할 수 있습니다.

작업 결과는 원본을 기준으로 처리 상태가 확정된 레코드입니다. 완료는 검토 사유 없이 반영되었거나 값이 같은 레코드입니다. 변경 필드는 규칙이 기록한 변경 경로 수이며 목록 전체 교체는 1개로 집계합니다. 원본/보완은 서로 다른 입력이고 오류는 양쪽에 기록될 수 있어 카드를 합산하지 않습니다. 보고서는 인터넷 없이 동작하며 `reports` 폴더 전체를 함께 보관하세요.

## 실행

- Windows 실행 파일: `dist/v2.17/LabelPorter.exe`를 더블클릭합니다. Python 설치가 필요하지 않습니다.
- 소스 실행: Python 3.11 이상에서 `python -m label_porter` 또는 `start.cmd`를 실행합니다. 먼저 `python -m pip install -r requirements.txt`로 문서 뷰어 의존성을 설치합니다. Windows 공식 Python의 Tkinter를 사용합니다. 실행 파일에는 문서 뷰어가 내장되어 별도 설치가 필요 없습니다.
- 상세 규칙 설명: [사용설명.md](사용설명.md)
- 후처리 가능 수준과 제한: [후처리_지원범위.md](후처리_지원범위.md) — 프로그램의 사용 방법 화면에도 포함됩니다.

## 화면에서 사용하기

**‘데이터로 규칙 만들기’에서 서로 다른 필드도 연결할 수 있습니다.** 원본 폴더와 플랫폼/보완 파일을 선택 → 연결 기준 추천 또는 직접 선택 → 반영 항목 체크 또는 직접 연결 → 검색·페이지별 실제 전후 확인 → 규칙 생성 → 기존 전체 검증·저장으로 이어집니다. AI나 별도 네트워크 연결이 필요하지 않습니다. 생성한 규칙은 ‘규칙 내보내기’로 저장할 수 있습니다.

- JSON / JSONL / NDJSON, 개별 파일·통합 배열·일반적인 records/rows/items/data 래퍼를 지원합니다. 원본 폴더의 JSON 계열 확장자는 한 종류씩 선택합니다.
- 연결 기준의 누락·중복·연결 수는 전체 입력을 검사합니다. 필드 위치는 구조 표본에서 탐색하고, 변경 예시는 앞 200개 연결 쌍을 사용합니다. 추천이 없어도 ‘직접 선택’으로 원본·보완 KEY를 따로 고를 수 있습니다. 값이 다르면 연결 수 0으로 표시하며 행 순서로 짝짓지 않습니다.
- 추천 항목을 먼저 표시하고 ‘다른 항목도 보기’ 또는 검색으로 표본의 다른 공통 항목을 찾습니다. 선택하지 않은 값은 원본 유지입니다.
- ‘다른 필드 연결’에서 원본 대상과 가져올 보완 필드를 선택합니다. ‘선택한 연결 수정’으로 연결과 빈 값 처리 정책을 바꿉니다. `importData_*`는 가져온 원본 값일 수 있으므로 실제 수정 입력값을 확인하세요. 단일 항목 내부를 연결하면 배열 길이 검사도 생성합니다.
- 선택한 목록은 순서·ID·추가·삭제·빈 목록·내부 추가 필드까지 보완본 그대로 반영합니다. 시간 반올림, ID 재부여, 전사 재생성, 태그 참조 검사를 자동 추가하지 않습니다. 어절의 음수·역전 시간 검사는 선택할 수 있습니다.
- 단계·도움말 이동과 생성 후 필드 연결 프리뷰에 읽은 데이터를 재사용합니다. 외부 파일 변경은 ‘데이터 새로 읽기’, 최종 저장 전에는 전체 검증을 사용합니다.
- 자료형 변환·복잡한 조건·반복 목록 내부 재구성·모호한 레코드 위치·표본에 없는 필드는 아래 AI 규칙 경로를 사용합니다. 전체 결과를 저장하기 전에 처리 결과서를 확인하세요.

**AI 규칙 파일을 사용하는 방법:**

1. 왼쪽 아래 **사용 방법 → AI 규칙 작성 가이드**에서 MD를 저장하거나 복사해 원본·플랫폼/보완 데이터와 함께 AI에게 전달합니다.
2. **규칙 파일 불러오기**로 `project_profile.json`을 엽니다. 곧바로 입력 단계로 이동합니다.
3. 전체 원본 폴더, 플랫폼/보완 파일들, 저장 위치를 선택합니다.
4. **필드 연결**과 **필드 연결 프리뷰**를 확인합니다. 전체 목록을 자동으로 불러오며 KEY·파일명·JSON 내용 검색, 연결 상태 필터, 페이지 이동을 지원합니다. 외부에서 파일을 변경했다면 ‘데이터 새로 읽기’를 누릅니다.
5. **다음 단계 → 전체 데이터 검증 → 처리 결과서 → 복사본 저장** 순서로 진행합니다.

규칙을 고칠 때는 원하는 변경을 설명하고 가이드·현재 규칙·예시 데이터를 AI에 전달합니다. 새로운 규칙 JSON을 받아 다시 불러옵니다. 프로그램 자체에는 AI 호출이나 데이터 외부 전송 기능이 없습니다. 기존 규칙 문법과 원본 보존·분리·보고서 기능은 유지됩니다.

자세한 내용은 [사용설명.md](사용설명.md)를 참고하세요.

## 출력

자주 누르는 미리보기와 보관해야 할 반영 결과를 구분합니다.

```text
선택한 저장 폴더/
  미리보기/               가장 최근 미리보기 보고서 (다음 미리보기 때 갱신)
    reports/
    profile.json
    manifest.json
    run_status.json
  2026-10-19/
    001/                  이날 첫 번째 반영
      data/               원본 폴더 구조를 유지한 전체 복사본
      changed/labels/     검토 사유 없이 실제 변경된 라벨
      unchanged/labels/   값 동일 라벨
      examine/unmatched/     짝이 없는 데이터
      examine/review/        검토 / 오류
      examine/excluded/      조건 제외
      examine/file_errors/   파일 단위 오류
      reports/
        report.html       분류별 검색·페이지 이동이 있는 처리 결과서
        catalog.json      원본·보완·출력·완료·검토·누락·변경 필드 목록
        record_details.jsonl 모든 처리 항목의 원본·보완·출력 JSON
        detail.html       공통 레코드 상세 화면
        detail_data/      필요할 때만 불러오는 상세 데이터 묶음
        summary.json      기계가 읽는 집계
        records.csv       전체 상태·누락·중복·검토 사유
        changes.jsonl     필드별 변경 전후 값
        review_details.jsonl 전체 검토 사유·원본·플랫폼·실제 출력·후보 JSON
        review/           검토 레코드별 비교 HTML 및 전체 JSON
        partition_index.jsonl 원본 ↔ 분리본 위치
      profile.json        적용 규칙
      manifest.json       원본/결과 해시
      run_status.json     완료·검토·실패·중단 상태
    002/                  이날 두 번째 반영
  2026-10-20/
    001/                  다음 날 첫 번째 반영
```

저장 위치를 지정하지 않으면 실행 파일 옆 `results` 폴더를 사용합니다(소스 실행은 프로젝트 폴더의 `results`). 직접 선택한 저장 경로에는 `포팅결과`를 덧붙이지 않습니다. 해당 경로 아래의 날짜·순번 및 미리보기 구조는 유지됩니다.

날짜는 **한국 시간** 기준입니다. 순번은 같은 날짜 폴더의 가장 큰 숫자 다음으로 발급하며 999 다음에는 1000입니다. 미리보기는 순번을 사용하지 않습니다. 기존 실제 반영 결과와 이전 버전의 `run_...`, `preview_...` 폴더는 이동하거나 삭제하지 않습니다.

미리보기의 보고서·설정·명세는 최신 실행으로 갱신됩니다. 보관할 미리보기 보고서는 다음 검증 전에 따로 복사하세요. 같은 저장 위치에서 동시에 미리보기를 실행하면 두 번째 실행을 차단합니다. 프로젝트마다 저장 상위 폴더를 따로 지정하면 프로젝트별 최신 미리보기를 유지할 수 있습니다.

실패/중단된 반영에는 부분 복사본이 남을 수 있으며, `run_status.json`과 HTML 보고서에 표시합니다. 다음 실행은 새 순번으로 저장됩니다. 실패/중단된 결과를 완성본으로 사용하지 마세요.

통합 JSON은 레코드 단위로, 개별 JSON은 파일 단위로 분리합니다. 원래 파일명·상대 경로·라벨 구조를 유지하며 통합 JSON의 바깥 메타데이터는 변경하지 않습니다. 검토·오류·연결 누락 대상은 `examine`에 분리하며 정상 변경/미변경 그룹에 중복으로 넣지 않습니다. 결과 없는 원본과 원본 없는 보완 데이터는 따로 집계합니다. 검토 대상에 연결된 보완 데이터도 분류별 `results`에 1건씩 저장합니다. `labels`는 처리 전 원본이고, 실제 처리 후 값은 `data`에 있습니다. 정상 데이터 분리를 꺼도 examine은 저장합니다. 미리보기는 분리 예정 집계만 계산하고 데이터 파일을 만들지 않습니다.

분리 대상은 라벨 JSON입니다. 원본 폴더에 함께 들어 있는 다른 파일은 전체 `data/` 복사본에 보존합니다. 별도 원천데이터 폴더를 연결하거나 이미지·오디오를 두 그룹으로 분리하는 기능은 없습니다. 예전 규칙 파일의 `assets` 설정은 불러올 때 제외되며 라벨 반영 규칙은 유지됩니다.

## 보존 및 검증 정책

- 결과에 없는 원본은 그대로 보존하며 `no_result`로 보고합니다. 이것만으로 작업 누락이라고 판정하지 않습니다.
- 원본 키/결과 키가 중복되면 임의로 하나를 선택하지 않습니다. 관련 항목 전체를 보존하고 보고합니다.
- 빈 수정값·필드 누락·자료형 오류·동일성 확인 실패·시간 범위/참조 오류는 `review_required`입니다.
- 레코드 내 여러 필드 중 하나라도 실패하면 해당 레코드의 모든 변경을 취소합니다. 다른 정상 레코드는 반영할 수 있습니다.
- 원본의 다른 필드와 메타데이터, 미디어 파일, 결과에 없는 파일은 유지됩니다.
- 결과에 없는 배열 항목은 기본적으로 검토 대상입니다. 부분 결과임이 확실한 프로젝트는 `require_same_keys: false`로 기존 항목을 보존하며 처리할 수 있습니다.
- 새 객체 ID, 어절 분할/병합의 자동 추정은 하지 않습니다. 관계를 정의한 새 규칙/확장 작업이 필요합니다.
- 설정은 임의 Python/JavaScript를 실행하지 않습니다. 지원하는 연산만 사용합니다.
- 수정된 JSON의 공백/들여쓰기/숫자 표기 등 직렬화 표현은 달라질 수 있습니다. 구조·값·자료형을 보존하며, 수정되지 않은 파일은 바이트 그대로 복사합니다.

## AI로 프로젝트 규칙 만들기

[AI_규칙작성_가이드.md](AI_규칙작성_가이드.md)는 별도 파일 하나로 AI에 전달할 수 있습니다. 데이터 역할 확인, 고유 키와 필드 대응, 허용 문법, 배열 객체 연결, 단위 변환, 보존 정책, 검증 절차와 반환 형식을 정의합니다. 문서의 텍스트·객체·시간 구간 예제는 가상 구조이며 실제 프로젝트에 맞춰 작성하도록 안내합니다.

## 저장소에 포함하는 파일

소스 코드, 테스트와 가상 데이터, 규칙 예제, 사용 설명서, 빌드 설정을 관리합니다. 실제 라벨 데이터, 플랫폼 내보내기 파일, 검증 보고서, 실행 파일, 가상 환경, 개인 설정과 인증 정보는 포함하지 않습니다.

작업 데이터는 저장소 밖에 두거나 `.gitignore`에 지정된 `data/`, `inputs/`, `results/`, `outputs/` 폴더를 사용하세요. 개인 프로젝트 규칙은 `local_profiles/`에 보관하세요. `profiles/`는 배포용 예제이며 특정 작업에 적용하기 전에 조건을 확인해야 합니다. `.gitignore`는 임의 이름의 민감한 파일을 자동 판별하지 않으므로 커밋 전에 추가 파일 목록을 확인하세요.

## 적용 범위

원본은 JSON 기반 라벨링 파일을 지원합니다. 단일 객체, 배열, 중첩 레코드, JSONL, 여러 JSON 객체가 공백으로 이어진 파일을 처리합니다. 결과 입력은 같은 JSON 종류와 CSV를 지원합니다. CSV의 중첩 JSON 열은 설정에 명시해 해석합니다. 이미지·오디오·LLM·3D의 구분보다 **원본과 결과의 연결키, 수정할 필드, 단위, 객체 관계**가 설정의 기준입니다.

임의의 신규 스키마를 의미까지 자동 추론하는 프로그램은 아닙니다. 이미 보완된 구간 분할·병합과 객체 추가·삭제는 목록 재구성 규칙으로 반영할 수 있습니다. 분할·병합 관계의 의미 추론, XML/독자 바이너리 해석, 좌표계 회전은 전처리나 추가 개발 대상입니다. JSON 객체/배열 전체 교체도 명시적으로 설정할 수 있지만 내부 참조와 누락 항목을 프로젝트에서 검증해야 합니다.

## 분류별 개별 후처리 파일

`examine`은 `unmatched`(짝 없음), `review`(검토/오류), `excluded`(조건 제외), `file_errors`(파일 오류)로 나뉩니다. 분류는 중복 없이 저장하며 파일 단위 오류를 먼저 구분합니다.

- 각 분류의 `labels/원본 상대경로/00000001.json`에는 수정 전 원본 레코드를 **1건씩** 저장합니다. 원래 파일이 배열·중첩 구조였다면 해당 구조와 메타데이터를 유지합니다. 파일 번호는 원본 파일 내 레코드 순번입니다.
- `results/입력파일 식별값/00000001.json`에는 검토 대상에 연결된 보완 레코드를 **1건씩** 저장합니다. 검토·조건 제외에도 원본과 보완 양쪽을 각각 보관하며, 짝이 없으면 존재하는 쪽만 저장합니다. 중복 KEY 후보도 각각 저장하고 같은 이름의 입력 파일은 서로 섞이지 않습니다.
- `details/00000001.json`은 검토 사유·비교 근거 문서입니다. `examine_sources`와 `examine_results`에서 해당 건의 원본·보완 파일 경로를 확인합니다. 라벨 데이터로 재사용할 파일은 `labels`와 `results`에 있습니다. `reports/partition_index.jsonl`(정상 분리 옵션을 끈 경우 `examine_index.jsonl`)은 원본 주소와 개별 출력 파일을 연결합니다.
- 해석할 수 없는 파일은 `file_errors/files/source` 또는 `file_errors/files/results`에 파일 자체를 복사합니다. 읽을 수 없어 복사가 불가능한 경우 details에 오류를 기록합니다.

전체 결과는 기존처럼 `data`에 보존합니다. 정상 변경/미변경 분리 옵션을 꺼도 위 분류는 저장하며, 검증 미리보기에서는 파일을 생성하지 않고 보고서에 분리 예정 경로를 기록합니다. 이전 버전의 결과 폴더 구조는 자동 변경하지 않습니다.

검토용 `labels`와 `results`는 각각 입력의 필드·배열/객체·중첩 구조와 바깥 메타데이터를 유지합니다. 통합 JSON 전체를 복사하지 않고 해당 레코드만 남깁니다. 한 건짜리 입력은 파일 바이트를 그대로 복사하며, 여러 건에서 추출할 때는 들여쓰기·숫자 표기 등의 직렬화 형식은 달라질 수 있습니다. JSONL/NDJSON은 한 건의 줄 단위 파일로, CSV는 헤더와 해당 행으로 저장합니다. 처리된 값이 일부 반영되어도 `examine/labels`는 수정 전 원본이며, 처리 후 값은 `data`와 상세 보고서에서 확인합니다. 레코드 경계를 확인할 수 없는 파일 오류에 한해서는 안전하게 자를 수 없으므로 입력 파일 전체를 `file_errors/files`에 보관합니다.
